# 介面風格規範：方案 B「清爽成長」

> 2026-11-12 開會紀錄 #49 第 4 項：「介面風格、排版調整（簡潔清晰），AI 感太重」。
> **2026-11-26 決定採用方案 B「清爽成長」**（參考 [huashu-design 風格庫](https://github.com/alchaincyf/huashu-design/tree/master/assets/style-specimens) 的樣張；借的是版式與氣質，配色由我們的嫩芽圖示推導，不照抄樣張）。
> 套用工作在 #64；這份是規則，每改一頁都對照這份。

## 1. 方案 B 由哪些風格組成

| 用在哪裡 | 參考樣張 | 借什麼 |
|---|---|---|
| 全站基調 | `app/10-native-polish`（Things 3 式） | 純白、清單為主、一個主色；行與行之間一條髮絲線；**用久了不累** |
| 學生端：關卡與進度 | `web/04-friendly-candy` | 關卡路線、進度條、圓潤的主要按鈕；**不照用它的綠黃藍**（那是 Duolingo 的配色），改用我們的嫩芽綠 |
| 學生端：成長感 | `paradigm/07-character-carries-state` | **嫩芽圖示依通過的關卡數長大**（種子 → 發芽 → 兩片葉 → 開花），進度就是嫩芽的樣子 |
| 老師端：後台頁面 | `web/15-utility-colorful-docs` | 左側分頁、清楚的表格、提示框；分類色收斂到 3 個以內 |
| 老師端：圖表 | `info/12-open-research-data` | 圖表標題寫結論、副標寫資料口徑、線尾直接標名稱（不用圖例）、非重點灰掉、底部寫來源 |
| 全站：顏色的意義 | `paradigm/04-one-semantic-color` | **整站只有一組語義色**：好／注意／警告；其他一律灰階 |

## 2. 為什麼原本看起來「AI 感」重

| 來源 | 例子 | 處理 |
|------|------|------|
| 標題前的裝飾 emoji | 📋 模組關卡進度、💡 分層提示、📊 AI 評分回饋 | ✅ 已拿掉 |
| 內部文件編號、技術用語 | 「待複核學生初評清單 (需求書 ASM-002)」、「AI 規準引擎串流評估」 | ✅ 已改成白話 |
| 深藍底配螢光色 | `#0f172a` 底、`#4ade80`／`#fbbf24`／`#7dd3fc` 的亮色字與半透明色塊 | ⏳ 改成白底、低飽和（第 3 節） |

## 3. 色彩

**來源**：主色取自老師提供的嫩芽圖示 `#2a9763`。嫩芽綠配白字的對比只有 3.68:1（不到無障礙標準 4.5:1），所以**按鈕與文字用加深的 `#1f7a50`**（5.31:1），原色只用在圖示、進度條、大面積色塊。

| 用途 | 色碼 | 對比（對白底） | 說明 |
|---|---|---|---|
| 頁面背景 | `#f7f8f7` | — | 帶一點綠的極淺灰，和白色卡片分得開 |
| 卡片、區塊 | `#ffffff`，邊框 `#e6e9e7` | — | 不用陰影光暈；需要浮起的只用一層淡陰影 |
| 主要文字 | `#1d1f1e` | 16.6:1 | |
| 次要文字 | `#5f6663` | 5.9:1 | 說明、時間、計數 |
| 主色（按鈕、目前頁籤、連結） | `#1f7a50`，滑過 `#186342` | 5.3:1 | 白字 |
| 品牌綠（圖示、進度條、嫩芽） | `#2a9763` | 3.7:1 | 不放小字 |
| 主色淡底（選取、徽章） | `#e8f5ee` | 字 `#1f7a50`：4.7:1 | |

**語義色（全站只有這三組，paradigm-04）**：

| 意義 | 字 | 底 | 對比 | 用在 |
|---|---|---|---|---|
| 好：通過、已完成 | `#1f7a50` | `#e8f5ee` | 4.7:1 | 通過、已發布、教師確認 |
| 注意：等待、快用完 | `#8a6100` | `#fdf4dc` | 5.1:1 | 待複核、次數或預算快用完、AI 信心偏低 |
| 警告：錯誤、擋下 | `#b3261e` | `#fbeaea` | 5.6:1 | 錯誤、個資被擋、預算用完 |

規則：
- 語義色以外的東西一律灰階；**不用顏色單獨表達意思**，要同時有文字或圖示（✓、!、✕）
- 「好」跟主色同一個綠：通過就是在長大
- 圖表的分類色最多 3 個（主色、`#8a6100`、`#5f6663` 的灰），非重點系列一律 `#c9cecb`

## 4. 字與排版

- 字型：`Noto Sans TC`（中文）＋ 系統無襯線（英數），不用襯線體
- 字級只用四種：頁面標題 22px、區塊標題 16px、內文 14px、說明 12px；粗體只給標題與數字
- 間距用 4 的倍數：區塊之間 16px、區塊內 12px；圓角卡片 12px、按鈕與輸入框 8px、徽章全圓
- 清單用「一行一件事」：左邊狀態、中間標題與一行說明、右邊數字或動作；行與行之間一條 1px 髮絲線 `#e6e9e7`（app-10）
- 表格靠左、數字靠右；表頭用次要文字色、不加底色
- 手機寬度（< 640px）一律單欄，按鈕至少 44px 高

## 5. 元件

| 元件 | 樣子 |
|---|---|
| 主要按鈕 | `#1f7a50` 底白字、8px 圓角；一個畫面只有一個主要按鈕 |
| 次要按鈕 | 白底、`#e6e9e7` 邊框、主要文字色 |
| 危險按鈕 | 白底、`#b3261e` 字；按下要確認 |
| 徽章 | 全圓、語義色的字＋底，例如「通過」「待複核」 |
| 進度條 | 底 `#e6e9e7`、進度 `#2a9763`、高 8px、全圓；旁邊寫數字（3 / 7 關） |
| 關卡路線（學生端，web-04） | 關卡依序排成一條線：已通過＝實心綠圈＋✓、目前＝綠框白底、鎖住＝灰圈＋鎖；不用發光 |
| 嫩芽成長（學生端，paradigm-07） | 依「已通過的必修關卡 ÷ 必修關卡」換圖：0% 種子、1–49% 發芽、50–99% 兩片葉、100% 開花；圖旁一句話（「再通過 2 關就長出第二片葉子」） |
| 提示框 | 左邊 3px 色條＋淡底；資訊用灰、注意與警告用語義色 |
| 圖表（老師端，info-12） | 標題是一句結論（「本月 AI 費用 8 成花在逐項評分」），副標寫單位與期間，線尾標名稱，底部寫資料來源 |

## 6. 文字語氣（借 app-11 的語氣，不借它的暗色）

- 用陳述與建議，不用命令和感嘆號：「這一關還差『具體行為』，補上就能通過」，不要「❌ 未達標！」
- 沒通過不用紅色；紅色只給真正的錯誤（個資、系統失敗）
- 不排名、不跟別人比較；進度只跟自己比
- 用老師與學生的話：構面 → 評分項目、Rubric → 評分規準、Session → 不出現
- 「AI」只出現在需要讓人知道「這是 AI 給的」的地方（AI 初評、AI 回饋、AI 整理）

## 7. 套用順序（#64）

1. 共用樣式：把上面的色碼與字級收成一組共用設定（CSS 變數），各頁不再寫死顏色
2. 共用元件：`AdminNav`、`StudentModeTabs`、頁首、按鈕、徽章、提示框
3. 學生端：登入 → 系統選擇 → 我的課程（關卡路線＋嫩芽）→ 作答區與聊天室
4. 教師端：課程管理 → 課程分頁（監控、複核、模組、教材、AI 用量、匯出）→ 建立機器人
5. 圖表：AI 用量、學習監控改成 info-12 的寫法

每改一頁都用桌機與手機寬度截圖對照，並請一位沒看過系統的人試用 3 分鐘，說說哪裡看不懂。
